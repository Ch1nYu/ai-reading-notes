## 完整摘要

### 資安核心：CIA 原則與三大災難
作者以一句話定義資安：無論外部如何惡意操作，系統功能必須正常且資料受保護。並列舉三種典型災難：資料被偷看（機密性 Confidentiality 失守）、規則被竄改（完整性 Integrity 失守）、服務被癱瘓（可用性 Availability 失守）。這三者合稱 CIA 原則，為後續威脅建模提供核心思考方向。影片並未深入探討 CIA 之外的進階模型（如 STRIDE），故此處僅作為入門基準。

### 上線前的五個核心問題
作者將安全檢視歸納為五個問題：1. 哪些資產一旦外洩會造成重大損失（API Key、未公開影片、用戶憑證、點數餘額、資料庫密碼）；2. 誰能存取哪些資產，需同時落實身份驗證與授權，避免只做登入檢查而漏掉資料歸屬驗證；3. 資料流經哪些區段，劃定信任邊界，所有涉及資產的決策（如點數扣除、付款驗證）必須在可控後端執行；4. 系統有哪些絕對不能被打破的底線（安全不變條件），例如同一筆付款只能入帳一次、點數不足不可啟動運算、不可跨權存取他人專案；5. 產品對外暴露哪些攻擊面（註冊頁、字幕生成、檔案上傳），並對應加上驗證碼、Rate Limit、檔案大小限制等防禦。這五問串連起完整威脅建模流程，但影片未示範如何將威脅模型文件化。

### Codex Security Plugin 安裝與掃描流程
作者介紹 OpenAI 官方推出的 Codex Security Plugin，安裝方式為在 Codex 插件商城搜尋「Codex Security」點擊安裝。掃描啟動指令為「請針對目前這個專案做一次 Codex Security 安全掃描」。關鍵在於必須先提供產品專屬的安全政策：可直接在對話框貼上規則，或在專案建立 Security.md 讓插件自動讀取；亦可使用內建 Define Security Policy Scale 由 AI 依程式碼反推政策。插件會順著資料流向追查攻擊路徑，僅在確認無其他防線時才輸出漏洞，減少誤報。影片未說明插件支援哪些程式語言或框架，亦未提及費用模式。

### 模擬報告中的兩項高風險漏洞
教學模擬報告列出八項風險，作者聚焦兩項 Hi 等級：第一，資料庫底層缺少用戶隔離機制（RLS, Row Level Security），導致繞過前端即可直接查詢他人資料；解法是在資料庫層級強制每列綁定擁有者，確保即使外圍防線失效，核心資料仍自我防衛。第二，扣點機制存在 Race Condition，系統在查詢餘額至扣款間有數秒窗口，攻擊者可並發請求超額消耗點數；修補方式為採立即預扣機制，確認餘額瞬間凍結點數，後續請求即被拒絕。影片以模擬報告為例，並非實際掃描結果，故具體程式碼位置與修復細節未公開。

### 四步驟修補流程與非技術者資安觀
作者提出日常開發四步驟：1. 專案完成時執行 Security Scan 全面體檢；2. 針對報告漏洞交由 Fix Finding 自動修補；3. 修補後用 Verify Fix 沿原攻擊路徑重新驗證，確保根治；4. 後續每次新增或修改程式碼執行 Security Deep Scan 專檢新增部分。並呼籲非技術背景者不應因缺乏程式能力而放棄資安，只要掌握 CIA 與五大問題思維，再善用 AI 工具即可建立紮實防線。影片未提供具體的 CI/CD 整合範例，亦未討論團隊協作時的政策版本控管。
